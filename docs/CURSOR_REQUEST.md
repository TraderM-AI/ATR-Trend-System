## 최종 요청 프롬프트

```
너는 TradingView Pine Script v5 전문가야.
아래 지표를 "일반 배포(퍼블리시)용" 품질로 검수하고 개선해줘.

■ 프로젝트
- 파일: indicators/btc_eth_atr_trend_v7.pine
- 원본: v6.7 (50배 고정, ATR 슈퍼트렌드 기반 롱/숏 전환 시스템)
- 대상: BTC/ETH 무기한 선물, 고배율(30x/50x) 단기 매매
- 형태: 오버레이 지표(indicator). strategy로 바꾸지 말 것

■ 시스템 정의 (변경 금지 — 이게 이 지표의 정체성이다)
1. ta.supertrend(multiplier, atrPeriod)의 direction으로 추세를 판정한다
   (direction == -1 → 상승/롱, direction == 1 → 하락/숏)
2. 추세가 전환되면 기존 포지션을 종료하고 즉시 반대 포지션으로 스위칭한다 (항상 포지션 보유)
3. 포지션 유지 중 목표 ROE에 도달하면 "마일스톤"을 포지션당 1회만 표시한다
4. 슈퍼트렌드 트레일링 라인을 항상 그린다

■ 범위 제외 (절대 추가하지 말 것)
- 청산가 계산, 청산 라인, 청산 경고, 유지증거금률 관련 기능 일체 → 넣지 마
- 수수료/슬리피지를 마일스톤 임계값이나 ROE 계산에 반영하지 마
  → 마일스톤은 "목표 ROE 도달을 알리는 표식"일 뿐이고, 총수익(gross) 기준으로 계산한다
  → 익절 신호도, 청산 신호도 아니다
- 부분 익절, 본전 스톱 이동 같은 자금관리 로직도 넣지 마

■ 필수 요구사항
[R1] 레버리지 선택 기능
     - input.string("50x", options=["30x", "50x"]) 로 사용자가 선택
     - 원본의 하드코딩된 (targetRoe / 50) 나눗셈을 전부 제거하고 선택값 기준으로 계산
     - 필요 가격변동 = (목표ROE / 레버리지) / 100
       → 30x: 7/30 = 0.2333% , 50x: 10/50 = 0.2000%
[R2] 레버리지별 마일스톤 기본값
     - 30배 → +7% ROE 도달 시 마일스톤
     - 50배 → +10% ROE 도달 시 마일스톤
     - 두 값 모두 인풋으로 변경 가능 (기본값이 7 / 10)
[R3] 마일스톤 라벨 텍스트를 선택값에 맞게 동적 표시
     - 30x 선택 시 "+7%", 50x 선택 시 "+10%" (하드코딩 문자열 금지)
     - plotshape의 text는 상수만 받으므로 label.new()로 분리해 뒀다.
       동작과 max_labels_count 한도를 검증해줘
[R4] 정보 패널(table): 레버리지 / 마일스톤 ROE / 필요 가격변동 / 현재 포지션 / 마일스톤 도달 여부

■ 반드시 고쳐야 할 결함 (원본 v6.7의 버그 — v7.0에 1차 반영했으니 검증하고 보강해줘)
[B1] 리페인팅: 진행 중인 봉에서 시그널이 떴다 사라진다.
     barstate.isconfirmed 게이트 옵션(기본 ON)이 모든 상태 갱신(pos/entryPrice/entryBar/
     milestoneHit)을 감싸고 있는지 확인하고, 과거 봉 계산에는 영향이 없는지 검증해줘.
     옵션 ON/OFF 각각의 동작 차이도 설명해줘.
[B2] 워밍업 오판: direction이 na인 초기 봉에서
     trend = direction == -1 ? 1 : -1  이 하락(-1)으로 고정돼 가짜 첫 전환이 발생했다.
     trend = na(direction) ? 0 : (direction == -1 ? 1 : -1) 로 판정 보류 상태 0을 도입했는데,
     이 0 상태에서 진입/종료/플롯이 모두 안전한지 확인해줘.
[B3] 마일스톤 오탐: entryPrice가 진입 봉의 close인데 같은 봉의 high/low와 비교해서,
     진입 전에 이미 지나간 가격으로 마일스톤이 즉시 찍혔다.
     entryBar를 기록해 bar_index > entryBar 인 봉부터만 판정하도록 했는지 검증해줘.
[B4] 상태 리셋 누락: 종료 시 pos만 0으로 바꾸고 entryPrice/entryBar/milestoneHit가 남았다.
     전부 리셋되는지 확인해줘.
[B5] 표식 중첩: 추세 전환 봉에서 종료 깃발과 반대방향 진입 화살표가
     같은 위치(abovebar)에 겹쳐 그려졌다.
     종료를 라벨(실현 ROE % 포함, 총수익 기준)로 바꿔 겹침을 없앴는데,
     진입 화살표와 시각적으로 충돌하지 않는지 확인하고 더 나은 배치가 있으면 제안해줘.
[B6] 알림 부재: 진입 2종 / 마일스톤 2종 / 종료 2종 alertcondition이 전부 있고
     메시지가 한국어로 명확한지 확인해줘. 알림은 봉 마감 기준임을 안내 문구에 반영.
[B7] 배포 품질: input group / minval / step / tooltip 정리,
     색상은 전부 input.color로 커스터마이즈 가능하게.
     (color.white는 화이트 테마에서 안 보이는 문제가 있으니 기본값 대안도 제안해줘)

■ 검수 체크리스트 (하나씩 결과를 보고해줘)
1. Pine v5 문법 오류 / 컴파일 에러 여부
2. if 블록 안에서 선언한 변수의 스코프 문제 (plot 계열은 전역에서만 호출 가능)
3. var 변수 초기화·리셋 누락
4. na 전파로 인한 조건식 오작동 (특히 entryPrice, entryBar, stLine)
5. series vs simple 타입 불일치
6. label.new 개수 한도(max_labels_count) 초과 가능성
7. 30x ↔ 50x 전환 시 과거 시그널이 일관되게 재계산되는지
8. 포지션당 마일스톤이 정확히 1회만 나오는지 (연속 추세에서 중복 표시 없음)

■ Phase 2 (이번엔 구현하지 말고 "설계안"만 제시해줘)
P1. strategy 버전 동시 제공 — 승률/MDD/PF 백테스트 검증용 (별도 파일)
P2. 횡보장 휩쏘 필터 — ADX 임계값 / EMA 기울기 / 최소 ATR% 중 무엇이 적합한지 근거와 함께
P3. 권장 심볼·타임프레임 가이드 (0.2% 임계값은 일봉에서 무의미함)
P4. 레버리지 옵션 확장 시(10x/20x/25x/75x/100x) if-else 체인이 길어지지 않는 구조

■ 산출물

## 후속 요청용 짧은 프롬프트 모음

**컴파일 에러가 났을 때**
```
아래 Pine v5 컴파일 에러를 고쳐줘. 로직은 유지하고 최소 변경으로 수정한 뒤,

[에러 메시지 붙여넣기]
```

**레버리지 옵션을 늘릴 때**
```
레버리지 옵션에 10x, 20x, 25x, 75x, 100x를 추가하고
마일스톤 기본 ROE를 레버리지별로 매핑할 수 있게 구조를 바꿔줘.
if-else 체인이 길어지지 않도록 배열이나 매핑 함수로 정리해줘.
청산 관련 기능은 추가하지 마.
```

**백테스트 검증본이 필요할 때**
```

strategies/btc_eth_atr_trend_v7_strategy.pine 로 만들어줘.
- 진입은 신호 다음 봉 시가
- calc_on_every_tick=false
- BTCUSDT.P 15분봉 기준 승률/MDD/PF 확인용
- 마일스톤은 지표와 동일하게 표식으로만 (익절 주문으로 만들지 마)
```

**퍼블리시 설명문이 필요할 때**
```
이 지표의 트레이딩뷰 퍼블리시 설명문을 한국어로 써줘.
포함할 것: 작동 원리, 인풋 설명, 시그널 읽는 법, 권장 심볼·타임프레임,
리페인팅 정책(봉 마감 기준), 마일스톤은 총수익 기준 표식이며 익절/청산 신호가 아니라는 고지.
