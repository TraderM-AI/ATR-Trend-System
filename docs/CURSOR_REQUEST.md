## 요청 프롬프트

```
너는 TradingView Pine Script v5 전문가야.
아래 지표를 "일반 배포(퍼블리시)용" 품질로 검수하고 개선해줘.

■ 프로젝트
- 파일: indicators/btc_eth_atr_trend_v7.pine
- 원본: v6.7 (50배 고정, ATR 슈퍼트렌드 기반 롱/숏 전환 시스템)
- 대상: BTC/ETH 무기한 선물, 고배율(30x/50x) 단기 매매
- 목적: 유저에게 배포할 지표. "표시된 수익률과 실제 수익률이 다르다"는 클레임이 없어야 함

■ 시스템 정의 (변경 금지 — 이게 이 지표의 정체성이다)
1. ta.supertrend(multiplier, atrPeriod)의 direction으로 추세를 판정한다
   (direction == -1 → 상승/롱, direction == 1 → 하락/숏)
2. 추세가 전환되면 기존 포지션을 종료하고 즉시 반대 포지션으로 스위칭한다 (항상 포지션 보유)
3. 포지션 유지 중 목표 ROE에 도달하면 "마일스톤"을 1회만 표시한다 (표식이지 청산이 아님)
4. 오버레이 지표(indicator)이며 슈퍼트렌드 트레일링 라인을 항상 그린다

■ 이번에 반드시 반영할 요구사항 (필수)
[R1] 레버리지 선택 기능
     - input.string("50x", options=["30x", "50x"]) 로 사용자가 선택
     - 기존의 하드코딩된 나눗셈 (targetRoe / 50) 을 전부 제거하고 선택값 기반으로 계산
[R2] 레버리지별 마일스톤 기준값
     - 30배 → +7% ROE 도달 시 마일스톤
     - 50배 → +10% ROE 도달 시 마일스톤
     - 두 값 모두 사용자가 인풋으로 바꿀 수 있어야 함 (기본값이 7 / 10)
     - 필요 가격변동 = (목표ROE / 레버리지) / 100
       → 30x: 7/30 = 0.2333% , 50x: 10/50 = 0.2000%
[R3] 마일스톤 라벨 텍스트를 선택된 기준에 맞게 동적으로 표시
     - 30x 선택 시 "+7%", 50x 선택 시 "+10%" 로 보이게 (하드코딩 문자열 금지)
     - plotshape의 text는 상수만 받으므로 label.new()로 분리해 뒀다. 동작과 라벨 개수 한도를 검증해줘
[R4] 정보 패널(table)에 현재 레버리지 / 마일스톤 기준 / 필요 가격변동 / 왕복비용 /
     청산까지 거리 / 현재 손절거리 / 상태를 표시

■ 반드시 고쳐야 할 결함 (원본 v6.7의 문제점 — 이미 v7.0에 1차 반영했으니 검증하고 보강해줘)
[B1] 리페인팅: 진행 중인 봉에서 시그널이 떴다 사라진다.
     barstate.isconfirmed 게이트 옵션(기본 ON)이 모든 상태 갱신(pos/entryPrice/milestoneHit)을
     감싸고 있는지 확인하고, 과거 봉 계산에는 영향이 없는지 검증해줘.
[B2] direction이 na인 워밍업 구간에서 trend가 -1(하락)로 오판되어 가짜 첫 전환이 발생했다.
     trend = na(direction) ? 0 : (direction == -1 ? 1 : -1) 로 판정 보류 상태를 두었는데,
     이 0 상태에서 진입/종료/플롯이 모두 안전한지 확인해줘.
[B3] 마일스톤 오탐: entryPrice가 진입 봉의 close인데 같은 봉의 high/low와 비교해서,
     진입 전에 이미 지나간 가격으로 마일스톤이 즉시 찍혔다.
     entryBar를 기록해 bar_index > entryBar 인 봉부터만 판정하도록 했는지 검증해줘.
[B4] 수수료·슬리피지가 전혀 반영되지 않아 "+10%"가 실제로는 +4.5% 수준이다.
     (50x 기준 왕복 0.11% 가격변동 = 5.5% ROE)
     "순수익 기준 마일스톤" 옵션이 임계값에 왕복비용을 더하고 있는지,
     종료 시 표시하는 실현 ROE에서도 비용을 빼고 있는지 확인해줘.
[B5] 청산 리스크가 로직에 없다. 이게 구조적으로 제일 위험하다.
     - 50x 청산거리 ≈ 1.6% (1/50 − MMR 0.4%), 30x ≈ 2.93%
     - ATR(14)×3.0 슈퍼트렌드 손절거리는 BTC 15분봉에서 흔히 1.5~4%
     → 손절선에 닿기 전에 청산되는 조합이 정상 범위에서 발생한다
     청산 추정가 라인 + (손절거리 > 청산거리)일 때 배경 경고 + 알림이 제대로 동작하는지 검증하고,
     더 좋은 시각화 방법이 있으면 제안해줘.
[B6] 종료 시그널(깃발)과 반대방향 진입 화살표가 같은 봉·같은 위치에 겹쳐 그려진다.
     겹침을 없애고, 종료 라벨에는 실현 ROE(%)를 함께 표시해줘.
[B7] 알림이 하나도 없었다. 진입/마일스톤/종료/청산위험 alertcondition이
     전부 있고 메시지가 한국어로 명확한지 확인해줘.

■ 검수 체크리스트 (하나씩 결과를 보고해줘)
1. Pine v5 문법 오류 / 컴파일 에러 여부
2. if 블록 안에서 선언한 변수의 스코프 문제 (플롯 함수는 전역에서만 호출 가능)
3. var 변수 초기화·리셋 누락
4. na 전파로 인한 조건식 오작동 (특히 entryPrice, entryBar, stLine)
5. 시리즈/단순값(series vs simple) 타입 불일치
6. plotshape / label.new 개수 한도 (max_labels_count) 문제
7. 30x ↔ 50x 전환 시 과거 시그널이 즉시 재계산되어 일관되게 바뀌는지
8. 리페인팅 옵션 ON/OFF 각각에서 결과 차이 설명

■ Phase 2 (이번엔 구현하지 말고 "설계안"만 제시해줘)
P1. strategy 버전 동시 제공 — 승률/MDD/PF 백테스트 검증용
    (진입가를 다음 봉 시가로, 수수료/슬리피지 commission_value 반영)
P2. 부분 익절 구조 — 마일스톤 도달 시 50% 익절 + 본전 스톱 이동
P3. 횡보장 휩쏘 필터 — ADX 임계값 / EMA 기울기 / 최소 ATR% 중 무엇이 적합한지 근거와 함께
P4. 레버리지 자동 추천 — 현재 ATR% 대비 청산거리를 계산해 30x/50x 중 안전한 쪽을 제안
P5. 권장 심볼·타임프레임 가이드 (0.2% 임계값은 일봉에서 무의미함)

■ 산출물
```

## 참고 — 커서AI가 알아야 할 계산값

| 항목 | 30x | 50x |
|---|---|---|
| 마일스톤 ROE | +7% | +10% |
| 필요 가격변동 (총수익) | 0.2333% | 0.2000% |
| 왕복 비용 (편도 0.055% 가정) | 3.3% ROE | 5.5% ROE |
| 필요 가격변동 (순수익) | 0.3433% | 0.3100% |
| 청산 추정 거리 (MMR 0.4%) | 2.93% | 1.60% |

계산식:
```
필요 가격변동(총수익) = (목표ROE / 레버리지) / 100
왕복 비용(가격변동)   = (편도수수료% + 편도슬리피지%) × 2 / 100
필요 가격변동(순수익) = 총수익 기준 + 왕복 비용
청산 거리            = 1 / 레버리지 − 유지증거금률
```

## 후속 요청용 짧은 프롬프트 모음

**컴파일 에러가 났을 때**
```
아래 Pine v5 컴파일 에러를 고쳐줘. 로직은 유지하고 최소 변경으로 수정한 뒤,
왜 발생했는지 한국어로 설명해줘.
[에러 메시지 붙여넣기]
```

**레버리지 옵션을 더 늘릴 때**
```
레버리지 옵션에 10x, 20x, 25x, 75x, 100x를 추가하고,
마일스톤 기본 ROE를 레버리지별로 매핑할 수 있게 구조를 바꿔줘.
지금처럼 if-else 체인이 길어지지 않도록 배열이나 매핑 함수로 정리해줘.
```

**백테스트 검증본이 필요할 때**
```
indicators/btc_eth_atr_trend_v7.pine 과 시그널이 100% 동일한 strategy 버전을
strategies/btc_eth_atr_trend_v7_strategy.pine 로 만들어줘.
- 진입은 신호 다음 봉 시가
- commission_type=strategy.commission.percent, commission_value=0.045
- slippage 반영
- calc_on_every_tick=false
- BTCUSDT.P 15분봉 기준 승률/MDD/PF를 확인할 수 있게
```

**퍼블리시 설명문이 필요할 때**
```
이 지표의 트레이딩뷰 퍼블리시 설명문을 한국어로 써줘.
포함할 것: 작동 원리, 인풋 설명, 시그널 읽는 법, 권장 심볼·타임프레임,
고배율 리스크 고지, 리페인팅 정책, 마일스톤이 청산 신호가 아니라는 점.
투자 권유로 읽히지 않게 중립적으로.
```
