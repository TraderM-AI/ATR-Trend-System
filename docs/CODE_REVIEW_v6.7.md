# v6.7 코드 리뷰 — 문제점 & 개선점

대상: `BTC/ETH ATR Trend System (v6.7 Color Custom)` / Pine Script v5 / 배포(퍼블리시) 목적

심각도: 🔴 배포 전 반드시 수정 · 🟡 배포 품질 저하 · 🟢 선택 개선

> **정책 결정 (확정)**
> - 청산 신호·청산가 표시는 **범위에서 제외**한다.
> - 마일스톤은 **목표 ROE 도달 표식**일 뿐이며, 수수료·슬리피지를 반영하지 않은
>   **총수익(gross) 기준**으로 표시한다. 익절/청산 신호가 아니다.
>   → 이 정책은 퍼블리시 설명문에 한 줄로 고지한다.

## A. 로직 결함 (전부 수정 대상)

### 🔴 A-1. 리페인팅 — 실시간 봉에서 시그널이 나타났다 사라짐
`ta.supertrend()`의 `direction`은 진행 중인 봉에서 틱마다 바뀝니다.
`longCondition`/`shortCondition`이 확정되지 않은 봉에서 평가되므로 화살표가 떴다가 봉 마감 시 사라집니다.
`var` 상태값(`pos`, `entryPrice`)도 실시간 봉에서 롤백/재계산되어 깜빡입니다.
→ 배포 지표에서 가장 많이 들어오는 클레임 항목.

**해결**: `barstate.isconfirmed` 게이트 옵션(기본 ON)으로 모든 상태 갱신을 감쌈.

### 🔴 A-2. 워밍업 구간에서 `direction`이 `na`일 때 하락추세로 오판
```pinescript
trend = direction == -1 ? 1 : -1
```
`direction`이 `na`인 초기 봉에서 조건이 거짓 처리되어 `trend = -1`(하락)로 고정됩니다.
차트 시작 지점에 실제 추세와 무관한 가짜 첫 전환이 발생합니다.

**해결**: `trend = na(direction) ? 0 : (direction == -1 ? 1 : -1)` — 판정 보류 상태 0 도입.

### 🔴 A-3. 진입 봉에서 마일스톤이 즉시 찍히는 오탐
`entryPrice = close`(진입 봉 종가)인데 같은 봉의 `high`/`low`와 비교합니다.
그 고가/저가는 **진입 이전에 이미 지나간 가격**입니다.
변동성 큰 봉에서는 진입하자마자 "+10%"가 찍히는 허위 표식이 나옵니다.

**해결**: `entryBar`를 기록하고 `bar_index > entryBar`인 봉부터만 판정.

### 🟡 A-4. 종료 시 `entryPrice` / `entryBar` 미초기화
`pos := 0`만 하고 나머지 상태는 남습니다. 지금은 `pos` 가드로 가려지지만
기능을 추가하는 순간 바로 버그가 되는 구조입니다.

**해결**: 종료 시 `entryPrice`, `entryBar`, `milestoneHit` 전부 리셋.

### 🟡 A-5. 종료 깃발과 반대방향 진입 화살표가 같은 봉·같은 위치에 중첩
추세 전환 봉에서 `longRev`(주황 깃발)와 `shortCondition`(노란 삼각형)이 동시에 그려집니다.
같은 `abovebar` 위치라 겹쳐서 읽기 어렵고 정보도 중복입니다.

**해결**: 종료는 라벨로 전환하고 **실현 ROE(총수익 기준)** 수치를 함께 표기.

## D. 레버리지별 기준값 (v7.0)

| 항목 | 30x | 50x |
|---|---|---|
| 마일스톤 ROE | +7% | +10% |
| 필요 가격변동 | 0.2333% | 0.2000% |

계산식: `필요 가격변동 = (목표ROE / 레버리지) / 100`

> 참고: 30배 +7%가 50배 +10%보다 **더 큰 가격 변동**을 요구합니다(0.233% vs 0.200%).
> 두 기준은 난이도가 다르며, 30배 쪽이 도달 빈도가 낮습니다. 설명 문구에 명시할 것.
