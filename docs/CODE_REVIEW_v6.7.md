# v6.7 코드 리뷰 — 문제점 & 개선점

대상: `BTC/ETH ATR Trend System (v6.7 Color Custom)` / Pine Script v5 / 배포(퍼블리시) 목적

심각도: 🔴 배포 전 반드시 수정 · 🟡 배포 품질 저하 · 🟢 선택 개선

---

## A. 로직 결함

### 🔴 A-1. 리페인팅 (실시간 봉에서 시그널이 나타났다 사라짐)
`ta.supertrend()`의 `direction`은 진행 중인 봉에서 틱마다 바뀝니다. `longCondition`/`shortCondition`이
확정되지 않은 봉에서 평가되므로, 화살표가 떴다가 봉 마감 시 사라질 수 있습니다.
`var` 상태값(`pos`, `entryPrice`)도 실시간 봉에서 롤백/재계산되어 깜빡입니다.
→ 배포 지표에서 가장 많이 들어오는 클레임 항목입니다.

**해결**: `barstate.isconfirmed` 게이트 옵션(기본 ON). 알림도 "봉 마감 시" 기준으로 안내.

### 🔴 A-2. 워밍업 구간에서 `direction`이 `na`일 때 하락추세로 오판
```pinescript
trend = direction == -1 ? 1 : -1
```
`direction`이 `na`인 초기 봉에서 조건이 거짓 처리되어 `trend = -1`(하락)로 고정됩니다.
차트 시작 지점에 실제 추세와 무관한 가짜 첫 전환이 발생합니다.

**해결**: `trend = na(direction) ? 0 : (direction == -1 ? 1 : -1)` — 판정 보류 상태 0을 도입.

### 🔴 A-3. 진입 봉에서 마일스톤이 즉시 찍히는 오탐
`entryPrice = close`(진입 봉 종가)인데, 같은 봉의 `high`/`low`와 비교합니다.
그 고가/저가는 **진입 이전에 이미 지나간 가격**입니다. 변동성 큰 봉에서는
진입하자마자 "+10%"가 찍히는 허위 신호가 나옵니다.

**해결**: `entryBar`를 기록하고 `bar_index > entryBar`인 봉부터만 마일스톤 판정.

### 🟡 A-4. 종료 시 `entryPrice` / `milestoneHit` 미초기화
`pos := 0`만 하고 나머지 상태는 남습니다. 현재 로직에선 `pos` 가드로 가려지지만,
기능을 추가할 때 바로 버그가 되는 구조입니다.

### 🟡 A-5. 종료 플래그와 진입 화살표가 같은 봉에 중첩
추세 전환 봉에서 `longRev`(주황 깃발)와 `shortCondition`(노란 삼각형)이 동시에 그려집니다.
같은 위치(`abovebar`)에 겹쳐 가독성이 떨어지고, 정보량도 중복입니다.

**해결**: 종료는 라벨로 바꾸고 **실현 ROE 수치**를 함께 표기(정보량 추가).

## B. 실거래 정합성 (배포용에서 제일 중요)

### 🔴 B-1. 수수료·슬리피지 미반영 → "+10%"는 실제 +10%가 아님
50배에서 +10% ROE = 가격 0.2% 변동입니다. 그런데 바이낸스 선물 테이커 왕복 수수료만
0.045% × 2 = **0.09%**, 슬리피지까지 더하면 0.11% 수준입니다.

| 레버리지 | 마일스톤 표기 | 필요 가격변동 | 왕복 비용(ROE 환산) | 실제 손에 남는 ROE |
|---|---|---|---|---|
| 50x | +10% | 0.200% | 약 5.5% | 약 **+4.5%** |
| 30x | +7%  | 0.233% | 약 3.3% | 약 **+3.7%** |

표기 수익의 **절반 가까이가 비용**입니다. 이대로 배포하면 "표시와 실제가 다르다"는
정확한 지적을 받습니다.

**해결**: 수수료/슬리피지 입력값 + "순수익 기준 마일스톤" 옵션.
ON이면 임계값 = 목표변동 + 왕복비용(50x 기준 0.31%).

### 🔴 B-2. 청산 리스크가 로직에 전혀 없음 — 구조적으로 가장 큰 문제
50배의 청산 거리는 약 **1.6%**(1/50 − 유지증거금률 0.4%), 30배는 약 **2.93%** 입니다.
반면 ATR(14) × 3.0 슈퍼트렌드의 손절 거리는 BTC 15분봉에서 흔히 1.5~4%, 1시간봉이면 3~8%입니다.

> 즉 **손절선에 닿기 전에 청산되는 경우**가 정상 범위에서 발생합니다.
> 이 상태로는 "추세 전환 시 종료"라는 전제 자체가 성립하지 않습니다.

**해결**: 청산 추정가 라인 표시 + `손절거리 > 청산거리`일 때 배경 경고 + 알림.
근본적으로는 승수/타임프레임/레버리지 조합을 사용자가 눈으로 확인하고 고르게 만들어야 합니다.

### 🟡 B-3. 진입가 = 신호 봉 종가 (실제 체결가와 다름)
실제로는 다음 봉 시가에 체결됩니다. 백테스트/기대치가 낙관적으로 나옵니다.

### 🟡 B-4. 부분 익절·트레일링 구조 없음
마일스톤은 "찍고 지나가는 표식"일 뿐, 실제 운용 규칙(예: 목표 도달 시 50% 익절 후
본전 스톱)이 없습니다. 고배율에서는 이게 실적을 좌우합니다.

## E. 레버리지별 기준값 (v7.0)

| 항목 | 30x | 50x |
|---|---|---|
| 마일스톤 ROE | +7% | +10% |
| 필요 가격변동 (총수익 기준) | 0.233% | 0.200% |
| 왕복 비용 (0.055% 편도 가정) | 3.3% ROE | 5.5% ROE |
| 필요 가격변동 (순수익 기준) | 0.343% | 0.310% |
| 청산 추정 거리 (MMR 0.4%) | 2.93% | 1.60% |

> 참고: 30배 +7%가 50배 +10%보다 **더 큰 가격 변동**을 요구합니다(0.233% vs 0.200%).
> 대신 청산 거리가 1.8배 넓어 생존력이 높습니다. 이 트레이드오프는 설명 문구에 명시할 것.
